# 两层配置：域名与工作区

设置项并不都写在同一个地方。Open Cottage 使用**分层配置**，你需要区分：

| 层级 | 存在哪 | 跟着什么走 | 典型内容 |
|------|--------|------------|----------|
| **域名级（domain）** | 浏览器 IndexedDB（按当前网站主机名，如 `localhost`） | 跟着**这个浏览器 + 这个访问地址** | 常用模型预设、跨文件夹想共用的偏好 |
| **工作区级（folder）** | 工作区里的 `.cottage/config.json` | 跟着**文件夹**备份/拷贝 | 本项目打开了哪些能力、本项目治理设置等 |

合并时大致优先：**工作区 > 域名**（还有可选的 server 层，一般用户可忽略）。

<Callout kind="tip">当前设置页没有统一的“保存到域名 / 当前工作区”切换器；不同配置项的保存范围由功能本身决定，以上表格为准。</Callout>

## 用生活类比

- **域名级** ≈ 你在这台电脑的这个浏览器里的「个人默认偏好」  
- **工作区级** ≈ 「这个项目自己的设定」，换电脑把文件夹拷走，设定一起走  

例如：

- 你希望「不管开哪个文件夹，默认都用 DeepSeek 某一档」→ 适合放在**域名级预设**  
- 你希望「只有客户 A 的资料夹默认打开办公能力」→ 适合写在**该工作区配置**  

## 实际使用时注意

1. **换浏览器 / 清站点数据**：域名级配置和 Key 可能一起消失，工作区文件还在。  
2. **同一文件夹换电脑**：工作区配置还在；域名级预设与 Key 要在新浏览器重建。  
3. **两个工作区**：可以共用域名级模型预设，同时各自保留不同的 `enabledTools` 等。  

## 和 API Key 的关系

Key **单独**存在 `open-cottage-secrets` 这套 IndexedDB 里，**不会**写入 `.cottage/config.json`。  
配置层只引用「用哪个提供商 / 哪个预设」，不把密钥明文写进工作区。详见下一篇。
