# 模型、预设与 API Key

要让 Agent 动起来，你至少需要：**选一个提供商 →（自定义端点时填 API 地址）→ 填 Key → 选模型**。

## 三个容易混的词

| 概念 | 含义 |
|------|------|
| **提供商（Provider）** | 如 DeepSeek、OpenAI、Anthropic、通义等 |
| **模型（Model）** | 该提供商下的具体模型名 |
| **预设（Preset）** | 一套可命名的「提供商 + 模型 + 参数」组合，方便切换 |

你可以在设置里维护多个预设（例如「快模型」「强模型」），在聊天区快速切换。

![设置 → 模型配置：服务商与模型入口](/images/concept-model-settings.png)

## API Key 存在哪里？

**只存在当前浏览器的 IndexedDB**，库名约为 `open-cottage-secrets`。

| 会存 | 不会存 |
|------|--------|
| 各 LLM 提供商的 API Key | `.cottage/config.json` |
| 可选的 Base URL | Git 仓库 / 聊天记录明文 |
| 预设专属 Key、部分 MCP / 搜索密钥 | 自动上传到 Cottage 服务器（本产品无此默认行为） |

因此：

- 把工作区文件夹发给同事 → **不会**附带你的 Key  
- 换浏览器或清除站点数据 → **需要重新填 Key**  
- 用公司电脑要注意：别人若能登录同一浏览器配置文件，理论上能碰到本地密钥存储  

## 不想把 Key 放进浏览器？

可选路径：

1. **部署层自建网关**：由反向代理或后端安全地持有 Key，前端在模型配置中连接其公开的兼容 API
2. **Cottage Service 的 HTTP 代理**：按你的设置转发请求（Key 仍可由浏览器头携带，或按你的部署方式处理）  

详见 [Cottage Service](./cottage-service-concepts)。

## 模型列表从哪来？

界面通常会尝试从提供商接口拉取模型列表；失败时你可以手动填写模型名。国内/国际厂商列表见 [模型提供商与 Key](/guide/models-and-keys)。

## 和分层配置的关系

- 「当前用哪个预设 / 模型」可以保存在**域名级**或**工作区级**配置里  
- **Key 本身**始终在 secrets 存储，不进工作区文件  

见 [两层配置](./storage-layers)。
