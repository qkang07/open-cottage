# Documents, slides, and spreadsheets

Enable the **Office documents** capability when creating or editing Word documents, presentations, or spreadsheets. Put the source material in the workspace and state the intended output path, audience, format, and any files that must remain unchanged.

For a document, ask for a clear outline before a long draft when structure matters. For a presentation, decide the slide count and narrative first, then request one conclusion per content slide. Slides can use semantic layouts such as timelines, metric cards, comparisons, processes, chart insights, and dashboards, plus explicit shapes, connectors, workspace images, tables, and charts. For a spreadsheet, specify the required sheets, formulas, input sources, and checks.

A polished deck needs both consistency and rhythm. Keep title baselines, margins, typography, and backgrounds stable; assign two or three accent colors to fixed sections; then vary the main composition to fit the message. Useful patterns include a large chapter number, a statement with supporting metrics, one spotlight result with two evidence blocks, and an asymmetric two-project showcase. Avoid repeating the same card grid on consecutive content slides. Low-contrast watermarks and ghost numbers can be marked as decorative so they are not treated as readable body text by layout checks.

The presentation preview is an approximate browser rendering for spotting structural, overflow, overlap, contrast, and missing-resource problems; final font wrapping should still be checked in PowerPoint. For richer decks, V3 uses `version: 3` and `pipeline: "html-layout"`: constrained HTML/CSS is laid out in the browser, measured, and compiled into an editable native PPTX. HTML is an internal design and acceptance source, not a parallel deliverable. Use `draftOnly: true` to inspect a design draft, then submit it with `sourceDraftId`.

When using an existing deck as a reference, choose `content-only`, `inspiration`, `match-style`, or `native-template`. Style matching extracts fonts, colors, proportions, layouts, and repeated decoration; native-template also reuses masters, layouts, and untouched SmartArt, media, and animation parts where safe. Existing presentations are inspected first and edited by element, with slide insertion, deletion, duplication, and reordering available. SmartArt, media, OLE objects, animations, and transitions are preserved but remain read-only; unsafe source synchronization is reported as stale. The preview remains an approximate HTML/SVG rendering.

Preview the result in the workspace and inspect layout, density, alignment, formulas, and links before delivery. Use [plan mode](./spec) when the work has multiple inputs or approval stages.
