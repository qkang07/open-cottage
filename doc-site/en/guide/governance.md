# Review and approve changes

Staged review keeps proposed writes visible before they become workspace files. Inspect each change, its diff, and its destination; apply the changes you accept and discard those you do not. This is especially useful when a task creates or modifies several files.

Sensitive operations, such as deletion, pause for an explicit decision. Treat the approval card as a request to verify the exact action and target, not as a generic confirmation that the task may continue.

Keep important work under your regular backup policy. [Version History Beta](./history) can help inspect and restore workspace history, but it is not a backup replacement.
