# Contributing

Contributions to the frontend, optional companion service, documentation, and capability packs are welcome. Start by reading the product introduction so that public documentation does not advertise hidden or unconnected code as a released user feature.

Before making a change, trace the full impact area: state and data flow, all configuration and UI entry points, adjacent interactions, failure and recovery behavior, and compatibility with existing workspace data. Keep cross-entry behavior consistent unless a boundary is explicitly documented.

Report vulnerabilities privately through the process in the repository's security guidance rather than publishing a proof of concept in a public issue.
