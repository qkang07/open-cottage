# 安全说明

Open Cottage 在浏览器内运行 Agent：它会读写你授权的本地目录，并可能调用外部 LLM API、伴随服务和脚本能力。完整漏洞披露政策见开源仓库的 `SECURITY.md`。

## 数据与工作区

- 对话、工作区配置、附件与（启用后）版本历史保存在工作区 `.cottage/`，不会自动上传到项目服务器。
- Agent 只能访问你已授权的工作区；路径规范化会阻止 `..` 越界。
- 本地优先不等于永不联网：调用模型、搜索网页或连接伴随服务都可能发起网络请求。

## API Key

- API Key 仅存浏览器 IndexedDB，不写入 `.cottage/config.json`。
- 不希望 Key 留在浏览器时，可使用你自己部署的兼容网关或代理。
- 不要把 Key、包含 Key 的 `.env` 或工作区密钥文件提交到仓库。

## 写入、审批与审阅

- **Policy** 会按风险级别请求确认；默认破坏性操作需要人工允许。
- **暂存审阅** 可以先查看 diff，再决定是否应用写入。
- 批量删除、覆盖或外部网页操作前，仍应阅读待执行内容并确认范围。

## 脚本与伴随服务

- 脚本在 Web Worker 中运行，但不是强隔离沙箱；只批准你信任的脚本与来源。
- Cottage Service 默认监听本机地址；未加固鉴权与 TLS 时，不应暴露到公网。
- 公开部署前收紧监听地址、CORS 与 TLS，并限制代理目标范围。

## 上报漏洞

请勿在公开 issue 中贴漏洞细节。请按开源仓库 `SECURITY.md` 中的渠道私下说明影响范围与复现步骤。
