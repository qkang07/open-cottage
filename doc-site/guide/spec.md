# 计划模式做复杂任务

<StoryLead label="何时使用计划模式">

当任务跨多个文件、能力或步骤时，使用 **计划模式** 先生成一份可查看、可修改、可批准的计划。你确认后，才会在同一会话中按任务继续执行。

</StoryLead>

## 什么时候值得先计划

- 任务会跨多个文件或多种能力。
- 你想先对齐“做到什么算完成”。
- 你不希望它一开始就大范围改动。

日常问答或小改动，继续用 [对话模式](./chat) 就好。

<StoryBeat title="修改已提交的计划">

直接说“先停，第 3 步改成……”，或在计划卡中暂停、编辑并提交新 revision。路径范围、步骤依赖或验收标准发生变化后需要重新批准；旧 revision 不会继续执行。

</StoryBeat>

浏览器版不会把文件写入成功冒充成完整功能验证。文件回读、内容哈希、JSON 字段、交付清单和受限 Browser Worker 都只属于结构证据；Browser Worker 无论结果如何都不能让计划自动完成。没有受信的 functional 验证时，计划会明确列出未覆盖项；只有你选择“接受未验证项并完成”后才会结束。`npm test`、构建、类型检查或 lint 仍需在你的环境里完成。

批准范围内的非破坏性写入会自动执行，并由工作区排他锁、实际变更报告和检查点保护。删除、移动、外部副作用、动态越界路径或浏览器不支持 Web Locks 时仍会在写入前暂停。刷新或关闭页面后，系统只从完整的 commit/head 恢复，不会根据半写入的运行投影猜测进度。

“计划中心”集中显示当前工作区中的活动、暂停、待验收、已完成和已归档计划。归档中的未结束计划可以恢复；如果同一会话意外出现多个活动计划，系统不会静默选择其中一个，而会要求你明确打开目标计划。
