# Open Cottage 正式面世：把 AI 从聊天框，请到你自己的工作现场

> 在自己的浏览器里，打开自己的文件夹，让 AI 把自然语言变成真实、可核对的交付物。

过去一段时间，我们已经越来越习惯向 AI 提问。

它能解释概念，能起草文案，能给出代码，也能把一件复杂的事说得头头是道。但当对话结束，我们经常还要回到熟悉的工作流程里：复制答案、寻找文件、调整格式、逐项核对，再判断它到底有没有真正做完。

AI 给出了答案，却没有接住工作。

这正是我们做 **Open Cottage** 的原因。

我们想做的，不是另一个更会聊天的窗口，而是一张真正摆在用户身边的 AI 工作台：它能够进入你指定的本地文件夹，理解其中的内容，修改代码，整理资料，生成文档、表格、演示文稿和图表；更重要的是，它必须把结果留在你的工作现场，并让你看得见、审得清、做得了决定。

一句话介绍 Open Cottage：

> **在你自己的环境里，把自然语言意图稳定地变成可验证的结果。**

## 为什么叫 Cottage？

“Cottage”是一间小屋。

我们喜欢这个名字所代表的尺度感：它不是一座远在云端、规则由别人决定的黑盒工厂，而更像一间建在自己院子里的工作室。文件放在哪里、允许谁进门、使用哪一种模型、安装哪些工具，都由你决定。

AI 可以很强，但钥匙应该留在用户手里。

这也是 Open Cottage 从一开始就坚持的产品立场：**本地优先、人在回路、结果可核对。**

## AI 不只应该“说”，还应该“交付”

现实工作很少以一段聊天回复结束。

一位运营需要的，可能是一份可以直接继续修改的周报；一位老师需要的，可能是一套课程讲义和演示文稿；一位开发者需要的，是仓库里几处准确的代码改动；一位研究者需要的，则是一篇保存到本地、能够继续追溯来源的资料整理。

所以，Open Cottage 把**本地文件夹**而不是聊天记录作为工作的基本单位。

你选择一个目录，便同时划定了 Agent 的工作空间。它可以在授权范围内读取上下文、创建和修改文件；你可以从左侧浏览文件，在中间预览内容与变更，在右侧继续对话。最终成果不是一句“已经完成”，而是磁盘上真实存在的文件、可以审阅的差异，以及能够重新打开核对的内容。

这看似只是从“回答”向“执行”多走了一步，实际上改变了人与 AI 的关系：AI 不再只是一个临时顾问，而开始成为工作流程中的协作者。

## 一间开在浏览器里的本地 AI 工坊

Open Cottage 以浏览器作为主要的人机界面。它不要求你先适应一套沉重的新软件，也不试图接管整台电脑。你只需要使用 Chrome 或 Edge 桌面版，明确选择一个本地目录并授予访问权限，Agent 的活动范围便被约束在这个工作区内。

这里有一个容易被误解、但非常重要的区别：**运行在浏览器里，不等于运行在某个陌生的云端。**

Open Cottage 没有默认把整个工作区同步到自己的服务器。会话、工作区配置、附件等项目数据会保存在目录内的 `.cottage/` 中，可以随文件夹一起备份和迁移；模型 API Key 则保存在当前浏览器的 IndexedDB 中，不写进工作区，也不会因为你把项目发给别人而一并泄露。

当然，“本地优先”不等于“完全离线”。当你使用云端大模型、联网搜索或网页抓取时，相关请求仍会发送给你主动配置的服务提供商。Open Cottage 希望做的不是用一句口号抹掉这些边界，而是把边界讲清楚，把选择权交还给用户。

## 对国内用户，不做“海外产品的中文翻译版”

如果一款 AI 工具主要面向中国用户，仅仅提供中文界面是不够的。

模型能不能方便接入、网络环境是否现实、Windows 是否好用、数据能否留在自己手中、能不能连接企业已有的兼容网关，这些才决定了它能不能进入日常工作。

因此，Open Cottage 从模型层开始就保持开放。除了 OpenAI、Anthropic、Google、OpenRouter 等服务，它也原生考虑了国内常用选择，包括 **DeepSeek、Kimi、智谱 GLM、通义千问、豆包、百度千帆、腾讯混元、MiniMax、硅基流动、零一万物、阶跃星辰和百川智能**；如果你已经有自己的中转服务、公司内网网关或其他兼容接口，也可以使用自定义 OpenAI 兼容地址。

这意味着，Open Cottage 并不把用户锁定在某一家模型厂商上。你可以按成本、速度、中文能力、上下文长度和数据要求选择模型，也可以为不同任务保存不同预设。

在联网能力上，项目同样考虑了国内环境。搜索与网页抓取可以按配置选择不同路线；可选的 **Cottage Service** 能在本机提供搜索、跨域抓取、网页自动化和 HTTP 代理等增强能力。对于希望自行部署、使用内网服务或减少对单一平台依赖的个人与团队，这种结构会更从容。

## 我们如何让 Agent 变得“敢用”

一个 Agent 能做多少事，并不是衡量它是否成熟的唯一标准。更重要的问题是：当它开始修改真实文件时，用户敢不敢把工作交给它？

Open Cottage 为此做了几项刻意的设计。

### 1. 写入先暂存，看过再落盘

在默认的暂存审阅机制下，Agent 的文件改动可以先进入暂存区。你能够查看真实 diff，逐个核对文件，然后选择应用、编辑或丢弃。

这不是给 AI 增加一道形式上的流程，而是在确立一条基本规则：**生成结果的是模型，决定结果是否成立的是人。**

### 2. 危险操作必须经过权限闸门

工具按读取、写入、外部调用、破坏性操作等风险级别管理。删除之类的破坏性动作默认需要用户明确允许；如果你拒绝，操作不会执行，Agent 会收到被阻止的原因，再决定调整方案或回来询问。

权限不是一份藏在设置深处的声明，而应该出现在动作真正发生之前。

### 3. 复杂工作先对齐计划

对于小而明确的事情，可以直接使用对话模式，边做边看；对于步骤多、影响范围大、容易跑偏的任务，可以切换到计划模式。Agent 会先整理目标、步骤、风险与验收方式，等你批准后再继续执行。

计划的价值不是让过程显得隆重，而是在动手之前先回答三个问题：我们究竟要完成什么？准备怎么做？最后拿什么判断它做对了？

### 4. 领域能力按需开启

办公、代码改造、PDF、图表、深度研究、网页自动化等能力，被组织成一个个可独立启停的能力包。需要写 PPT 时打开办公能力，需要改仓库时打开代码能力，不相关的工具则保持关闭。

这样做会少一点“一键全能”的戏剧效果，却能换来更清晰的授权边界、更低的工具噪声，以及更稳定的模型选择。

我们相信，真正的通用 Agent 不应该是一只永远敞开的巨大工具箱。**通用的是平台的工作纪律，多样的是可以按需装入的领域能力。**

## 为什么不用一条万能命令解决一切？

给模型一套不受约束的系统命令，当然很自由。对于演示，它甚至可能是最短的路径；但对于长期使用，它也最难解释、最难审阅，更难建立稳定的信任。

Open Cottage 更偏爱面向具体任务的语义化工具：读取文件、应用补丁、生成演示文稿、写入表格、分析代码影响、抓取网页……每种工具都有相对清晰的输入、输出和风险级别。脚本能力仍然存在，但它更像处理特殊情况的工作台，而不是所有任务默认驶入的高速公路。

这背后是一个朴素的判断：**工具首先应该方便人理解，其次才是方便模型调用。**

如果一个系统只能让 AI 觉得自由，却让用户看不懂发生了什么，那么这种自由最终会变成使用者的负担。

## 它现在能做什么？

你可以把 Open Cottage 用在这些具体工作里：

- 打开一个资料目录，让它整理素材并生成 Markdown、Word、PPT 或表格；
- 在代码仓库里查找符号、分析影响范围，完成有边界的代码修改；
- 搜索和抓取公开网页，把结果整理成保存在本地的研究材料；
- 阅读、处理 PDF，生成图表或流程图，并在界面中直接预览；
- 使用图片理解与图片生成能力，为文档或创意工作补充视觉素材；
- 通过外部能力包、工作区 Skills 与 MCP，接入更具体的工具和工作规范。

这些场景共享同一套工作方式：**选定工作区，说明目标，按需开启能力，审阅过程，验收文件。**

## 它现在还不是什么？

Open Cottage 目前仍处于 `0.x` 的早期开发阶段。接口和数据格式仍可能变化，部分能力也需要继续打磨。

它还不是一个注册账号即可使用的成熟云服务。你需要准备 Node.js 20 及以上版本和 pnpm，并使用支持 File System Access API 的 Chrome 或 Edge 桌面浏览器；如果要获得更稳定的网页抓取与自动化能力，还可以自行运行 Cottage Service。

它也不是一个绝对安全的执行沙箱。Agent 生成的脚本虽然运行在 Web Worker 中，但这并非面对恶意代码的强隔离环境；对来源不明的脚本和高风险操作，仍应认真审阅。

把这些限制写出来，并不会削弱产品。相反，我们认为：一个强调信任的工具，首先应该诚实描述自己的能力边界。

## 从今天开始，让 AI 真正走进工作目录

在 Windows 上，可以从仓库根目录启动：

```powershell
.\start.ps1
```

在 macOS 或 Linux 上：

```bash
bash start.sh
```

随后打开 `https://localhost:5176`，选择一个本地文件夹，配置你常用的模型与 API Key，再按任务开启相应能力包，就可以开始第一段协作。

Open Cottage 采用 **MIT License** 开放。我们欢迎开发者参与平台与能力包建设，也欢迎每一位真正使用它完成工作的人告诉我们：哪些地方足够可靠，哪些地方仍然让你犹豫。

因为我们想做的，从来不是一场关于“AI 有多聪明”的表演。

我们更在意的是：当新鲜感退去，当工作变得具体，当文件真的要交付给同事、客户或自己时，这个 Agent 是否仍然值得留在你的浏览器里。

如果未来每个人都会拥有一间自己的 AI 工作室，我们希望 Open Cottage 是其中一间：

> **模型可以更换，能力可以生长，数据留在手边，决定始终属于你。**
